# Ordered Implementation Tasks

**Status:** Proposed backlog; do not start application implementation until `spec/spec.md` and `spec/plan.md` are approved.
**Task size:** Aim for one evening (about two hours) per task. Split any task that exceeds that budget before starting it.
**Per-task rule:** Re-read the constitution, relevant acceptance criteria, and plan section; state the intended change; write/adjust the acceptance test first; implement only that T-ID; run the focused check; record results and deviations. No commit requirement is added here because it was not approved as a working rule.
**Placeholders:** Test commands are established by M0 scaffold and may be adjusted only in the relevant approved task. Physical-device checks must record device/model/build identifiers and results.

## Cross-Task Gates

- No M1 ingestion implementation starts until T-006 records an approved embedding choice and exact evaluation artifacts.
- No model is downloadable from a production catalog until its exact source, quantization, commercial terms, attribution, and redistribution status are approved in the license register.
- No billing implementation starts until T-028 is approved, current Play requirements are rechecked, and the purchase-only network boundary/offline policy is signed off.
- SQLCipher, OCR, flashcards, spaced repetition, summaries, iOS, study packs, accounts, and cloud AI remain out of MVP tasks.
- Tasks are sequential unless `[P]` is present; parallel tasks must not alter the same integration surface. Each milestone ends in a demo and a spec/code gap review before the next milestone.
